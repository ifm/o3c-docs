Triggering

The O3C camera is built for precise timing at the system level. The 3D TOF image sensor is internally triggered, ensuring more precise timing than can typically be achieved with an external method, for example compared to software-triggering on ifm O3D3xx cameras over a network.

The O3C also provides a hardware trigger input that can be used to trigger acquisition externally.

Internally, the user-visible free-run mode is implemented as a triggered mode: a Trigger Control Unit (TCU) issues regular software trigger signals generated by the M7 real-time core of the iMX8MPlus. This is what provides the precise internal timing described above.

Both the 2D and 3D imagers are driven by this same internal TCU triggering. When the 2D and 3D imagers run in free-run at the same framerate, their acquisitions are synchronized.

The two imagers cannot be combined into a shared software-trigger group to be triggered at exactly the same moment. This is because the 2D camera cannot enter the IDLE state to wait for a trigger — it only supports the RUN and CONF states. The 3D imager, in contrast, can be placed in the IDLE state and then triggered on demand via the hardware trigger input or a software trigger.

States

3D triggering can operate in either the RUN or IDLE state.

In the RUN state, the 3D imager is triggered at regular intervals based on the framerate and delay parameters. This is also referred to as the free-running state, where the camera operates at the desired framerate.

In the IDLE state, the imager is inactive and an acquisition is taken only when a trigger signal is received — either from the hardware trigger input or from a software trigger.

Configuration

The trigger functionality can be configured with the following settings:

Parameter

Value

Description

framerate

1/sec

Acquisition framerate

delay

ms

Time offset applied to the acquisition trigger

The delay parameter specifies the minimum time interval in milliseconds between the default framerate loop and the image sensor trigger.

Overall system latency and repeatability

The typical overall sensor system latency depends on several factors:

  • Internal system latency and jitter:

    • Jitter of the system when in a free-running state,

    • Delay between the moment the trigger command is sent and when it is received.

  • External latency:

    • Network latency when sending trigger signals,

    • Network latency when sending data via the network.

  • Data processing latency: depends on the algorithm, application and hardware.

Note

The jitter for an O3C camera is approximately 1ms, and the framerate about 0.2ms.
